# Handoff

threeditor started as the `editor-experiment/` folder in `languel/threejslessons`. It now runs as a static three.js r187 workspace with a dedicated Script Window editor area, clip preview, presentation mode, and offline publishing.

## Run and deploy

- Run `python3 -m http.server 5300` from the repository root and open `/`. The root entry uses an `editor/` base so modules, assets, and older `/editor/` links keep working. Keep both entry HTML files in sync.
- GitHub Pages uses the Actions workflow in `.github/workflows/pages.yml`. A push to `main` assembles the static site and deploys it. The workflow can also be dispatched manually.
- Smoke-test the deployed editor, including the `/threeditor/` base path, at [GitHub Pages](https://languel.github.io/threeditor/).
- The editor still registers the upstream cleanup service worker. It unregisters itself and clears old caches. Hard-reload if an older session is serving stale modules.

## Projection mapping and modeling

- **Scans** use `assets/ScanFiles.js` to distinguish Gaussian PLY, vertex-only PLY, and PLY with faces. File Import and Assets share the same loader. The Gaussian runtime also loads SPZ, SOG, RAD and raw SPLAT. PCD and XYZ become editable Three.js point objects. Named saves and playable exports retain the source files used by attached behaviors.
- **Projectors** use the editable behavior in `assets/Projector.js`. It builds a textured spotlight from a calibration grid, still, or video. The rig aims along local −Z. A hand-drawn mask stores named aperture and cutout contours in normalized image coordinates. Legacy single-contour masks remain readable. The runtime applies warp, the target silhouette, the hand-drawn mask, and independent edge fades before uploading the texture. Generated scripts from older projects receive edge-blend and shadow tuning parameters on load. The projector runtime applies map resolution, depth and normal bias, and filter radius to its internal spotlight. The virtual spotlight and Masked texture output share that canvas. Gaussian splats and point clouds serve as spatial references.
- **Modeling** stores control points and polygon boundaries in `geometry.userData.modeling`. `modeling/ModelGeometry.js` derives line samples and render triangles. `ModelViewport.js` keeps viewport handles transient and commits geometry changes through undoable editor commands. Ordinary static meshes support vertex moves up to 20,000 buffer vertices. Authored polygon meshes expose face fill, split, and extrusion.
- **Light views and split** use `modeling/ViewLayout.js` to share one renderer across the director and a selected view. Derived light cameras stay out of project camera and export lists. Projector frames letterbox to the optical aspect, and the same rectangle drives masks and surface raycasts. The workspace restores the selected light and split preference from project JSON.
- **Viewport tools** use `modeling/ViewportTools.js` for in-view masks, HUD rulers, and surface marks. `Measurements.js` adapts Threegrease’s local-space bindings, length units, and oriented polygon area. Calibration stores metres per world unit in scene metadata. Surface paths and paint are native undoable child objects of the receiver.
- **Examples** live in `editor/examples/projection/`. The three public-domain Mediatheque assets ship with the scenes. `tools/build-projection-examples.mjs` rebuilds them from a sibling Mediatheque checkout and preserves source credits in the project Assets panel.
- **Captured spaces** live in `editor/examples/gallery/`. The builder verifies and bundles the DDA Gallery and Spatial Comp Room SPZ files, rotates them into the Y-up editor frame, and bakes only the approximate reference geometry. The DDA mapping scene uses a procedural canvas as the pedestal spotlight’s texture, two masked wall projections, and an animated WebGL SDF. Split views keep separate Gaussian depth sorting for each camera.

Run `node --test test/*.test.mjs` before pushing. For a browser smoke test, open **File → Examples → Projection mapping**. Move a ridge vertex in **Yosemite relief** and undo it, apply an inverted mask in **Canyon aperture**, then enter Play in **Gallop triptych** and confirm that the video advances across the three panels. The [example notes](editor/examples/projection/README.md) describe the scenes and their sources.

### ThreeGrease surface and topology interactions

- Surface Paint collects eligible scene receivers once per stroke. The brush uses a visible hit from `SurfacePicking.js`, and triangle receivers also get perimeter rays to clip the dab. Point clouds and Gaussian splats use point-depth dabs. Scan marks attach to the persistent scan rig so that changing scan display mode preserves them. Preview meshes are runtime-only. One paint stroke commits the receiver-local meshes without changing selection and undoes as a group.
- Topology Pen adapts ThreeGrease’s context-sensitive mesh operations to ordered face loops. `ModelViewport.js` distinguishes edge clicks, edge and face drags, and Ctrl-click insertion. `ModelGeometry.js` holds the split, poke, and weld mutations. Each drag previews transient geometry and commits only on pointer-up.
- `SculptBrush.js` applies weighted movement and adjacency for Grab, Push, Smooth, Relax, Pinch, and Twist. The standard keymap exposes Surface Paint, Edit, Sculpt, Topology Pen, Weld, and brush size. Hold Shift for temporary Smooth.
- Smoke-test one paint stroke across two receivers and undo once. Also paint an unlocked point cloud and a bundled Gaussian scan. On an authored mesh, click an edge to split it, pull a boundary edge, and Ctrl-click a face. On a dense mesh, switch from Push to Pinch and undo a stroke.

### Pencil and 2D painting

- Pencil uses shared placement settings. The viewport overlay resolves the same plane as the current stroke and follows the pointer. Mesh Surface follows the receiver and Surface Perpendicular locks at the first hit. View Plane can also hold depth from a projected path segment or endpoint. The stroke eraser batches whole-stroke removals into one history action. `PencilStroke.js` adapts the trailing pointer, screen-space drawing guides, endpoint-preserving smoothing, and simplification from ThreeGrease. The 3D postprocess applies to plane strokes so that averaging does not lift surface-bound strokes off their mesh.
- `PencilRibbon.js` builds a native mesh from the editable path and its pressure, tip, and surface samples. The geometry, brush metadata, and repeatable grain texture round-trip with the project. `PencilGrain.js` generates the shared texture source for brushes, UV and image painting, and editable SVG stroke patterns. Editing uses the common path geometry builder, and viewport shading preserves the ink material. `PencilSelection.js` projects the authored path for thin-stroke picking and region selection, including legacy Pencil lines.
- `PencilSplats.js` turns the same brush settings into oriented Gaussian kernels and uses the existing embedded splat loader and history commands. `PencilBrush.js` holds shared tip settings and the raster dab profile. `TexturePaint.js` uses the same material-copy and undo path for 3D and UV painting. Image & Vector records raster brush samples separately from editable contours and composites them for export.
- The Image & Vector and UV shelves share color sampling through `BrushColorSampler.js`. `CubeUV.js` provides the connected net shared by the authored Cube primitive and the UV layout for existing boxes. UV sculpt uses the same brush falloff and neighbor logic as mesh sculpt. `UVIslands.js` finds linked faces by their mesh and UV edges and keeps a shared buffer vertex together during transforms. Vertex dragging and sculpt weld corner records through matching UV edges, so islands that touch at a single point can be edited independently. Sculpt can protect island perimeters, and manually pinned buffer corners persist in the source geometry after Apply. The UV editor stores authored seam edges by local endpoint coordinates in geometry metadata. The unwrap add-on uses corner connectivity across uncut edges so a seam can split a UV vertex inside a connected chart. `Canvas2DTools.js` supplies the shared pan, zoom and 2D transforms for the UV, Warp, Image & Vector, and Mask work areas. The browser smoke test checks guide visibility, texture paint and erase, UV moves, and SVG paint export. Image & Vector keeps reference files in Project assets when applying a drawing and stores their path with the editable drawing data. The shared asset picker filters reference choices to still image files, reuses Project paths, and keeps the selector open if decoding fails. Closing the drawing workspace cancels its picker and pending image decode. Reference placement is normalized to the drawing frame and shared by the preview, PNG, SVG, and texture saves. Guide opacity affects only the preview. Placement edits support local undo and are stored on Apply. Save texture to Project assets snapshots the same PNG composition used for download. Both bitmap and SVG output include the reference only when requested, and the resulting PNG can use the standard material and projector asset assignment paths.

### Mode and tool layout

The app top bar owns the editor picker exposed by `EditWorkspace.js`. Script Window uses the same area, resize, and maximize controls as the other editors. `CodePanel.js` owns the persistent CodeMirror instance and preserves the active script and scene draft across area changes. `ViewportTools.js` builds one vertical shelf for persistent tools and a separate dropdown for immediate mesh operations. The mode picker exposes Object, Edit, Sculpt and Paint. The shelf follows the mode, and returning to Edit or Sculpt restores its last compatible tool. The pressed tool button identifies the active tool without an extra label. The T binding and View menu toggle the tool shelf independently of the transform row. Mode controls stay top-left, transform/grid controls center, and view controls top-right; a ResizeObserver puts transforms on a separate centered row when the viewport is narrow. Operation menus align glyphs and labels on one left-aligned row. Active shelf buttons use the same centered accent fill as transforms; keep their selector specific enough to override the nested theme Button rule. Glyphs for surface paint, sculpt, topology, curve, polygon, mesh, and freehand drawing are distinct.

The topology pen turns on when a mesh profile closes. Subsequent empty-space clicks collect a new face draft in the same object, reusing existing vertices when picked. Clicking the first corner or pressing F closes the face. Escape discards the draft. An uncommitted face stays outside serialized geometry.

`Keymap.js` resolves the active area from the pointer or keyboard focus. The mesh and viewport tool handlers use the same routing as F3. Active transforms retain their confirmation and cancellation keys. `Animation.js` shares timeline delete commands between the inspector buttons and shortcuts. The unified workspace check exercises Outliner hover during mesh editing, area-specific F3 results, and timeline key deletion and undo.

### Workspace tabs

`WorkspaceTabs.js` opens the existing modes, docks, and editors from the application header or command palette. Layout starts with a short timeline, Animation expands it, and Projection can put the selected projector or spotlight alongside the Director. The header wraps onto separate rows as space gets tight. Compact mode uses glyphs and all appearances share the flat active-tab fill. It shares one height with viewport positioning and top-menu auto-hide.

Material Preview uses authored materials and scene effects with normal editing guides. Live Preview keeps the same real-time scene rendering and hides the editing guides. The shading pie keeps Rendered, Solid, Material Preview, and Wireframe on 1–4, with Live Preview on 5. Saved shading IDs stay stable.

### Outliner and Properties

`Sidebar.Scene.js` supplies the Outliner and the Scene properties content. `Sidebar.js` docks them in independent regions. Search filters names and types while keeping matching ancestors and preserving collapsed branches. The Properties tabs follow selection and support arrow-key navigation. The Timeline spans the workspace to the left of the sidebar on desktop. In Assets, the Add assets disclosure keeps the preview visible in shorter panes.

### Selection feedback

`Viewport.SelectionOutline.js` adapts ThreeGrease's alpha silhouette pass. It renders selected roots with their own materials (including cutouts, point sprites and deforming meshes) and composites a two CSS pixel orange rim. SplatHost attaches the scan renderer during the isolated pass. All visibility, ancestor layers, render target, viewport, scissor, background, override material and shadow-update state are restored, including on exceptions. The selection pass runs in the Director editing view and its split companion. Preview, Play and exported output omit the selection overlay. Settings → General → Selection highlight defaults to Outline; optional bounds modes remain available. WebGPU/XR use the bounds fallback. Test selection and deselection, a child mesh under another mesh, transparent textures, multi-selection, split views and renderer replacement.

Object and Edit modes share region geometry and selection operations through `modeling/MeshSelection.js`. `modeling/ObjectSelection.js` projects eligible object origins into the pane where a gesture starts. The normal selector still owns selection and pivots. Removing a selection that includes both a parent and its descendants records the parent once, so undo restores the whole hierarchy.

Local View and temporary hides live in `modeling/ViewportVisibility.js`. The Director draw scopes visibility and restores it in a `finally` block, including ancestor layers used to keep selected child meshes visible. Selection, measurement, snapping, paint, and asset drops use the same filter. Optical views and Play continue to render the authored scene. Realistic Director mode uses raster preview while a filter is active.

The unified workspace stores the 3D Cursor in the editor snapshot as `cursor`. Projects saved by the earlier build with `cursor3D` are restored through the same loader. `ViewportTools.js` places the cursor, and `modeling/CursorSnap.js` supplies Shift+S snapping. The cursor pivot anchors the object group and mesh transform proxies.

### Profile building and extrusion

- `modeling/ModelViewport.js` draws and closes a pending mesh profile from the vertical tool strip. Closed paths and shapes can feed the same interactive extrusion. The pointer preview is transient. Confirm commits the underlying topology and cap movement together, and Escape drops the preview.
- `ModelGeometry.js` adapts ThreeGrease’s sheet underside and boundary strip behavior. It keeps the ordered face loops for editing, triangulates render geometry, and maps hit triangles back to their authored faces. Extruding a curve makes a separate editable mesh from its sampled outline.
- In a narrow viewport, use the **2D Editors** menu in the app’s top bar to enter Mask, Image and Vector, UV, or Warp. The menu stays anchored as the workspace changes. Drawing actions live in vertical tool strips, while view and transform settings stay horizontal. The Ground plane placement uses a down-arrow over a plane glyph.
- Smoke-test by closing a polygon from **Build mesh**, previewing and canceling a pull, entering an exact signed extrusion distance, and undoing. Close and extrude a smooth path. Check the workspace menu at desktop and narrow widths.

3D paths and shapes, 2D vectors, and projector masks use the same contour segment hit test and point insertion. `modeling/Contour.js` keeps the closing edge implicit. The 3D editor picks against rendered curve samples, preserves local coordinates, and commits through geometry history. The 2D editor applies its draft through its existing command, and projection and mask compositing retain their normalized image coordinates.

### Docked 2D editing

- `modeling/EditWorkspace.js` mounts Mask, Image & Vector, UV, and Warp. UV and Image & Vector default to a resizable split with the live 3D view when the available workspace is at least 640 pixels wide. All four can use the split through its header button. The 3D camera and any existing 3D split are retained on exit. UV follows another selected mesh after the current draft is applied. The modeling inspector can open the same modes. Apply saves the current draft and keeps the mode open.
- The 3D Edit Mode overlay redraws from the current camera while the 2D workspace is split. Clicking the 3D canvas releases focus from the 2D controls so shortcuts work in the viewport. The workspace browser check samples an orange vertex before and after divider movement and camera orbit, and checks selection and Escape in the 3D pane.
- Image & Vector reuses the drawing workspace in `MaskEditor.js`. It saves the vector contours in `scene.userData.vectorDrawing`. The local reference image is held in memory during editing. SVG exports the vectors, and PNG renders the shape and reference composite.
- Smoke-test by opening Mask from the viewport toolbar and applying a multi-shape mask, switching to UV on a selected mesh, then loading a reference in Image & Vector. Apply a colored contour, export SVG and PNG, and reopen the mode to confirm the contour persists. Use **3D View** to return, then test the projector in Play.

### UV unwrap and texture baking

The UV workspace stages edits before Apply. Unwrap from seams, Smart unwrap, and Lightmap pack reuse the bundled `unwrapUVs` utility. The seam-driven mode uses connected face components and the existing conformal solver across material boundaries. An unflattenable chart reports an error and leaves the staged layout intact. Browser checks open a curved two-material tube into one island and verify that a closed box needs seams or Smart unwrap. Pack existing islands uses the UV island selection topology and the same padded rectangle packer as unwrap. It moves and uniformly scales the staged coordinates with local undo, preserving buffer indices and edited island shape. Cube projection packs six directions, cylindrical projection separates flat caps, and sphere, planar, current-view and projector projections are available. Applying UVs to a mesh with a modifier stack updates its source and reevaluates the stack.

`modeling/TextureBake.js` adapts ThreeGrease’s camera-to-UV bake to a WebGL source render and a depth-tested UV-space pass. The neutral lighting guide uses authored lamp and shadow flags with neutral surfaces and ambient light. The projector pass samples the current masked and warped output and tests visibility against scene geometry. The PNG and optional unlit guide mesh use the current UV draft. A bake captures one view and one instant. Use an atlas without overlaps and apply mesh modifiers before baking. The browser check measures a lit pixel, a shadowed pixel, and the alpha under a projector occluder.

### Multi-shape masks

- `modeling/MaskEditor.js` handles the 2D workspace, scene outline picker, and draft undo. `MaskSculpt.js` adapts Poliplan’s local subdivision, brush falloff, Push, and Smooth to closed mask contours. **Apply masks** commits the draft through `setLightMask`.
- `projectionMask.shapes` stores each shape's name, operation, and points. `ProjectionMask.js` unions apertures and subtracts cutouts. The projector and spotlight script paths embed the same compositor. The viewport editor exposes a shape selector, and scene outline context actions append a shape.
- Smoke test through **Modeling → Pick scene outline** on an unlocked projector. Import a closed scene shape, overlap it with a drawn aperture, and draw a cutout through the overlap. Verify the overlap remains lit outside the cutout. Apply, undo, and check **Masked texture** in Play.

- Older autosaves and standalone project JSON files may require re-importing the original model and companion files for source publishing.
- Named User projects are local to a browser origin. They are not server-side files, and clearing site storage removes them. The JSON download embeds the serialized scene but does not retain original import files; the named browser copy and Editable HTML do. Portable editor files retain their original bundled example catalog and resources; hosted catalog updates require the hosted editor.
- Dependency discovery covers static imports and supported literal asset paths. Custom runtime code can require additional packaging support. A portable editor re-save retains the libraries bundled in the original HTML. Build with the hosted editor when adding new module dependencies or producing ZIP or Playable exports.
- Source publishing reconstructs the scene from its supported material, geometry, and lighting features. Use the serialized player for attached object behavior.
- Render Image's **Realistic** mode uses the experimental WebGPU path tracer in megakernel mode and requires WebGPU. A simple r187 scene and its default environment were rendered in Chrome; broader material, lighting, and device coverage remains unverified. The separate viewport Realistic mode still uses the older WebGL tracer and has not received the same compatibility work.
- When upgrading three.js, compare the editor and vendored build/addons against upstream and rerun the publish and import smoke tests.

## Interface design principles

- Controls share the panel backdrop. Buttons are transparent by default and gain a fill only on hover or when active, selected or pressed. Text inputs and number fields may keep a surface fill; dropdowns also share the backdrop.
- Active and selected states use a low-opacity accent tint, never a solid accent fill.
- Compact mode keeps one text size and weight, tight gaps, and a consistent footprint for icon buttons (28px minimum, 4px 6px padding). All glyphs, including menubar icons and the right-hand panel toggles, are 15px.
- Icons replace labels only through `Glyphs.js`, and the original text must remain as the hover tip.
- Code line numbers are deliberately dim (28% text over background) so they do not compete with code.
