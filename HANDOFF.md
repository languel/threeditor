# Handoff

threeditor started as the `editor-experiment/` folder in `languel/threejslessons`. It now runs as a static three.js r187 workspace with a docked Code panel, clip preview, presentation mode, and offline publishing.

## Run and deploy

- Run `python3 -m http.server 5300` from the repository root and open `/editor/`. Keep the trailing slash for the relative module and asset paths.
- GitHub Pages uses the Actions workflow in `.github/workflows/pages.yml`. A push to `main` assembles the static site and deploys it. The workflow can also be dispatched manually.
- Smoke-test the deployed editor, including the `/threeditor/` base path, at [GitHub Pages](https://languel.github.io/threeditor/editor/).
- The editor still registers the upstream cleanup service worker. It unregisters itself and clears old caches. Hard-reload if an older session is serving stale modules.

## Implementation map

| Area | Entry points and behavior |
| --- | --- |
| Startup | `editor/index.html` loads `EditorApp.js`. The same startup initializes hosted and packaged sessions. The hosted session restores IndexedDB state and retains imported source files in `editor.sourceFiles`. |
| Code and scripts | `CodePanel.js` keeps drafts separate from the last applied scene, validates and builds a candidate before swapping, and follows selection for object scripts and shaders. `CodeLanguageService.js` uses the bundled TypeScript worker and r187 definitions for completion and selected diagnostics. `ScriptParams.js` parses `@param` comments into editable per-script values passed as `params` in Play. Formatting and minimization use the bundled Prettier and Terser tools. |
| Camera and lighting | `Editor.toJSON()` saves the editor camera, viewport camera, active scene camera and navigation target. The director camera supports standard mouse orbit/pan/zoom and backtick/WASD fly navigation together. Viewport navigation supports parented cameras. Numpad 0 toggles the active camera view and Ctrl+Alt+Numpad 0 aligns it to the view. `CameraControllerScript.js` attaches editable Orbit, Fly, First Person or Third Person scripts to scene cameras from Object properties. The Script tab exposes speed, sensitivity, follow UUID, pan and zoom parameters. `APP.Player.setCameraController()` shares the player's update/resize/disposal lifecycle and accepts input only for the active camera. Legacy metadata controllers remain readable. Source exports retain presets and parameters; custom controller behavior requires playable exports. Play shares the viewport background and scene environment setup. |
| Assets | `AssetBrowser.js` offers stored project assets or Upload from texture slots and File → Import. `ProjectAssets.js` stores original files in `editor.sourceFiles` with companion batches. Autosave and editable HTML retain these files. |
| Examples and named projects | `ExampleCatalog.js` defines an ordered nested tree under File → Examples: original demos in `threejs`, six editor scenes in `lessons` (Fox last), and browser saves in `User`. `ExampleLibrary.js` renders searchable collapsible folders, opens projects with a DOM confirmation, and provides the Save dialog. `ProjectLibrary.js` stores independent snapshots and original source File objects in the separate `threeditor-projects` IndexedDB database, using atomic `projects`/`entries` transactions. Slash-separated names form nested User folders; the same path updates one snapshot. File → Save and Ctrl/Cmd+S download scene JSON and save the browser copy. Clearing the workspace only clears the existing autosave database, never the named library. `project.title` and `project.libraryPath` round-trip through JSON; `projectLoaded` updates project settings and schedules autosave. Browser storage errors keep the JSON download available and are shown in the save dialog. |
| Adapted lessons | `tools/build-lessons.mjs` builds cube, anatomy, recorded body, Triadic costumes and paint scenes from the source modules/recording vendored under `tools/lesson-sources/`, derived from `~/dev/threejslessons`. Camera and object matrices must be updated before serialization. Body/costume motion uses standard AnimationClips, and paint strokes are normal editable Lines. See `editor/examples/lessons/README.md` for scope and provenance: these are recorded editor adaptations, not the source pages' live tracking, depth or audio interfaces. Fox remains the sixth/final catalog entry and loads its original GLB into `sourceFiles`. |
| Workspace | `PanelDock.js` manages docked, collapsed, and overlay states; `MenuAutoHide.js` handles the optional top-edge menu reveal. `Animation.js` previews one active clip. `Sidebar.Settings.js` and `Theme.js` manage presets and saved palettes, including opacity and code editor colors. With translucent panels, the viewport extends behind them, changing its framing. Material base-color opacity maps to standard three.js material opacity and transparency. |
| Shortcuts and navigation | `Keymap.js` registers the editor actions and menu commands, persists independent Basic and Blender overrides, and resolves collisions. Mouse navigation is independent of the keyboard preset: `settings/mouseNavigation` defaults to Standard (left orbit, Shift-left/right pan, scroll zoom), with optional Blender middle-mouse navigation and Alt-left emulation. `Sidebar.Settings.Shortcuts.js` provides search and key capture. `ModalTransform.js` implements mouse-driven Blender G/R/S with axis constraints, accept/cancel and undo; it is not the full Blender transform system. `FlyControls.js` flies the actual viewport camera, including parented cameras, with cancel and scene-camera undo. Navigation hints are white shadowed text on a transparent viewport overlay, centered above the bottom toolbar. Mouse and keymap preferences travel with editable HTML. |
| Fox demo | `demos/fox-follow/` contains a standalone player, editable `scene.json`, and the mediatheque fox GLB with attribution. A Run animation mixer drives the fox while its parent follows a circular woodland trail. The follow camera uses an editable Third Person script. GitHub Pages includes `demos/`. |
| Agent harness | `AgentAPI.js` owns the shared `window.threeditor` registry and registers WebMCP tools where `document.modelContext` is available. Tools cover scene, UI, commands, code, PNG render, assets, scripts, project state and exports. WebMCP discovery and invocation were tested with Chrome's experimental `WebMCP` feature enabled, as well as a mock provider; no external agent was tested. The API is in-page, not an external MCP relay. |
| ZIP and playback | `Publish.js` validates supported module and asset dependencies. Source project generates JavaScript, while Playable scene serializes the scene and shares `libs/app-bootstrap.js` with Playable HTML. `SingleHtml.js` uses the vendored esbuild WASM for a single-file player. |
| Portable editor | `EditorHtml.js` bundles the editor and embeds the project, scripts, source files, and runtime assets. `PortableSession.js` restores them and saves a new HTML copy without rebuilding the editor bundle. Its presentation stack icon is hidden until hover or focus by default. The `project/presentationEditVisible` preference travels in the embedded config. |

## Verification and limits

Chrome smoke tests have covered editable and playable files opening offline, an animated GLB, glTF companion files, an object script with a packaged asset and module, disabled scripts, camera recovery, environment lighting, panel controls, custom theme persistence, translucent panel layout, menu auto-hide, material opacity undo/redo, and re-saving an edited HTML copy. WebGPU packaging has been checked at build time. Runtime playback checks used WebGL. Browser smoke tests currently run outside the repository.

Recent checks covered texture upload and reuse, OBJ re-import and autosave, Control-drag transform snapping, parented camera navigation and alignment, camera controller packaging, script parameters in standalone HTML, last-working-scene preservation, and matching Preview and Play background pixels. The language service and its definitions add approximately 15 MB to editable HTML exports.

Run `node --test test/*.test.mjs` for navigation and controller-script regressions (no dependency install needed). Six checks cover standard and Blender mouse gestures, explicit scene-camera controllers, parameter serialization/clamping, editable script execution, and source export settings/follow UUIDs. Browser checks also covered mouse orbit with Blender keyboard shortcuts, WASD fly followed by mouse orbit, controller parameter editing and persistence, scripted fox playback, pause/resume, and transparent viewport hint positioning. Hard-refresh existing tabs when checking changed modules or CSS; cached assets were observed during development.

The suite now contains ten checks, adding nested project paths/tree construction, detached scene-and-asset snapshots, catalog order, all example scene round-trips, lesson camera framing, and baked motion playback. Open `test/project-library.browser.html` on a local server and choose **Run IndexedDB checks** to verify real IndexedDB transactions, original File retention, independent connections, same-name updates and test cleanup. Browser UI checks covered nested threejs/lessons/User folders, named JSON download, saved subfolders surviving a new editor tab, and reopening a Fox save with its 162,852-byte original GLB, Third Person controller and playback intact.

- Older autosaves and standalone project JSON files may require re-importing the original model and companion files for source publishing.
- Named User projects are local to a browser origin. They are not server-side files, and clearing site storage removes them. The JSON download embeds the serialized scene but does not retain original import files; the named browser copy and Editable HTML do. Portable editor files retain their original bundled example catalog and resources; hosted catalog updates require the hosted editor.
- Dependency discovery covers static imports and supported literal asset paths. Custom runtime code can require additional packaging support. A portable editor re-save retains the libraries bundled in the original HTML. Build with the hosted editor when adding new module dependencies or producing ZIP or Playable exports.
- Source publishing reconstructs the scene from its supported material, geometry, and lighting features. Use the serialized player for attached object behavior.
- Render Image's **Realistic** mode uses the experimental WebGPU path tracer in megakernel mode and requires WebGPU. A simple r187 scene and its default environment were rendered in Chrome; broader material, lighting, and device coverage remains unverified. The separate viewport Realistic mode still uses the older WebGL tracer and has not received the same compatibility work.
- When upgrading three.js, compare the editor and vendored build/addons against upstream and rerun the publish and import smoke tests.

## Asset browser integration

The Assets sidebar replaces the old modal chooser. `Sidebar.Assets.js` owns Project/My assets/Mediatheque browsing; `assets/AssetController.js` resolves links into project source files, applies textures through `SetMaterialMapCommand`, and routes viewport drops. `assets/AssetLibrary.js` owns the independent `threeditor-assets` IndexedDB library. `assets/Mediatheque.js` adapts the AMS catalog/search/facet implementation from `languel/artistmodelstudio`; AMS was read from `/tmp/threeditor-ams-reference` because `~/dev/artistmodelstudio` was absent. The full catalog includes models, model animations, originals and BVH links. Default host is `https://languel.github.io/mediatheque/`, verified with `Access-Control-Allow-Origin: *`; the Catalog connection UI overrides it via `threeditor_mediatheque_base`.

`Loader.importGLTFAsset` shares the editor's Draco/KTX2/Meshopt configuration and adds the model as an undoable object without the scene-replacement dialog. Both GLB and glTF external resources are discovered before placement; uploads retain all companions in their batch, including `.bin` files. `assets/AssetTexture.js` is shared by native texture slots and browser material assignment. Viewport drops raycast against scene meshes, then the ground plane; images target the hit mesh material. Dragging over Scene/Material tabs exposes native texture slots. No original bytes are discarded: using a remote asset retains a project copy; named User saves and portable snapshots preserve source metadata. A local library copy retains companion paths as a batch. All catalog kinds are browsable, but SDF/splats/video/audio have link/download support only.

Validation: `node --test test/*.test.mjs` now has fifteen passing checks. Open `test/asset-browser.browser.html` and run its button for real IndexedDB File retention, live CORS Fox import (three animation clips), position and undo/redo, color/data texture handling, local and remote glTF sibling-directory dependencies, native texture-slot picking/drop, viewport drag routing, and named/portable project snapshots. It creates uniquely named test records and removes those records afterward. GUI checks also cover catalog search and the scrolling grid with its persistent asset inspector. Hard-refresh the editor after module/CSS changes.

The final export smoke test caught and fixed a stale flat-demo list in `EditorHtml.js`; it now uses recursive `exampleResources()` from `ExampleCatalog.js`, including lesson assets. Source ZIP and a 34.5 MB Editable HTML exported successfully; the standalone HTML reopened on a separate origin with original GLBs and reimported Fox with its animation clips.

The app remains available at `http://localhost:5300/editor/`. The separate exported-HTML QA server on port 5301 was stopped after the reopen check; no unrelated development servers were stopped. Deployment uses the GitHub Pages workflow on pushes to main.
