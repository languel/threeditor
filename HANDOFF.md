# Handoff

threeditor started as the `editor-experiment/` folder in `languel/threejslessons`. It now runs as a static three.js r187 workspace with a docked Code panel, clip preview, presentation mode, and offline publishing.

## Run and deploy

- Run `python3 -m http.server 5300` from the repository root and open `/editor/`. Keep the trailing slash for the relative module and asset paths.
- GitHub Pages uses the Actions workflow in `.github/workflows/pages.yml`. A push to `main` assembles the static site and deploys it. The workflow can also be dispatched manually.
- Smoke-test the deployed editor, including the `/threeditor/` base path, at [GitHub Pages](https://languel.github.io/threeditor/editor/).
- The editor still registers the upstream cleanup service worker. It unregisters itself and clears old caches. Hard-reload if an older session is serving stale modules.

## Implementation map

| Area | Entry points and behavior |
| --- | --- |
| Startup | `editor/index.html` loads `EditorApp.js`. The same startup initializes hosted and packaged sessions. The hosted session restores IndexedDB state and retains imported source files in `editor.sourceFiles`. |
| Code and scripts | `CodePanel.js` keeps drafts separate from the last applied scene, validates and builds a candidate before swapping, and follows selection for object scripts and shaders. `CodeLanguageService.js` uses the bundled TypeScript worker and r187 definitions for completion and selected diagnostics. `ScriptParams.js` parses `@param` comments and inline numeric ranges, and resolves saved per-script overrides for playback. Formatting and minimization use the bundled Prettier and Terser tools. |
| Camera and lighting | `Editor.toJSON()` saves the editor camera, viewport camera, active scene camera and navigation target. The director camera supports standard mouse orbit/pan/zoom and backtick/WASD fly navigation together. Viewport navigation supports parented cameras. Numpad 0 toggles the active camera view and Ctrl+Alt+Numpad 0 aligns it to the view. `CameraControllerScript.js` attaches editable Orbit, Fly, First Person or Third Person scripts to scene cameras from Object properties. The Script tab exposes speed, sensitivity, follow UUID, pan and zoom parameters. `APP.Player.setCameraController()` shares the player's update/resize/disposal lifecycle and accepts input only for the active camera. Legacy metadata controllers remain readable. Source exports retain presets and parameters; custom controller behavior requires playable exports. Play shares the viewport background and scene environment setup. |
| Assets | `AssetBrowser.js` offers stored project assets or Upload from texture slots and File → Import. `ProjectAssets.js` stores original files in `editor.sourceFiles` with companion batches. Autosave and editable HTML retain these files. |
| Examples and named projects | `ExampleCatalog.js` defines an ordered nested tree under File → Examples: original demos in `threejs`, six editor scenes in `lessons` (Fox last), and browser saves in `User`. `ExampleLibrary.js` renders searchable collapsible folders, opens projects with a DOM confirmation, and provides the Save dialog. `ProjectLibrary.js` stores independent snapshots and original source File objects in the separate `threeditor-projects` IndexedDB database, using atomic `projects`/`entries` transactions. Slash-separated names form nested User folders; the same path updates one snapshot. File → Save and Ctrl/Cmd+S download scene JSON and save the browser copy. Clearing the workspace only clears the existing autosave database, never the named library. `project.title` and `project.libraryPath` round-trip through JSON; `projectLoaded` updates project settings and schedules autosave. Browser storage errors keep the JSON download available and are shown in the save dialog. |
| Adapted lessons | `tools/build-lessons.mjs` builds cube, anatomy, recorded body, Triadic costumes and paint scenes from the source modules/recording vendored under `tools/lesson-sources/`, derived from `~/dev/threejslessons`. Camera and object matrices must be updated before serialization. Body/costume motion uses standard AnimationClips, and paint strokes are normal editable Lines. See `editor/examples/lessons/README.md` for scope and provenance: these are recorded editor adaptations, not the source pages' live tracking, depth or audio interfaces. Fox remains the sixth/final catalog entry and loads its original GLB into `sourceFiles`. |
| Workspace | `PanelDock.js` manages docked, collapsed, and overlay states; `MenuAutoHide.js` handles the optional top-edge menu reveal. `Animation.js` previews one active clip. `Sidebar.Settings.js` and `Theme.js` manage presets and saved palettes, including opacity and code editor colors. With translucent panels, the viewport extends behind them, changing its framing. Material base-color opacity maps to standard three.js material opacity and transparency. |
| Shortcuts and navigation | `Keymap.js` registers the editor actions and menu commands, persists independent Basic and Blender overrides, and resolves collisions. Mouse navigation is independent of the keyboard preset: `settings/mouseNavigation` defaults to Standard (left orbit, Shift-left/right pan, scroll zoom), with optional Blender middle-mouse navigation and Alt-left emulation. `Sidebar.Settings.Shortcuts.js` provides search and key capture. `ModalTransform.js` implements mouse-driven Blender G/R/S with axis constraints, accept/cancel and undo; it is not the full Blender transform system. `FlyControls.js` flies the actual viewport camera, including parented cameras, with cancel and scene-camera undo. Navigation hints are white shadowed text on a transparent viewport overlay, centered above the bottom toolbar. Mouse and keymap preferences travel with editable HTML. |
| Fox demo | `demos/fox-follow/` contains a standalone player, editable `scene.json`, and the mediatheque fox GLB with attribution. A Run animation mixer drives the fox while its parent follows a circular woodland trail. The follow camera uses an editable Third Person script. GitHub Pages includes `demos/`. |
| Agent harness | `AgentAPI.js` owns the shared `window.threeditor` registry and registers WebMCP tools where `document.modelContext` is available. Tools cover scene, UI, commands, code, PNG render, assets, scripts, project state and exports. WebMCP discovery and invocation were tested with Chrome's experimental `WebMCP` feature enabled, as well as a mock provider; no external agent was tested. The API is in-page, not an external MCP relay. |
| ZIP and playback | `Publish.js` validates supported module and asset dependencies. Source project generates JavaScript, while Playable scene serializes the scene and shares `libs/app-bootstrap.js` with Playable HTML. `SingleHtml.js` uses the vendored esbuild WASM for a single-file player. |
| Portable editor | `EditorHtml.js` bundles the editor and embeds the project, scripts, source files, and runtime assets. `PortableSession.js` restores them and saves a new HTML copy without rebuilding the editor bundle. Its presentation stack icon is hidden until hover or focus by default. The `project/presentationEditVisible` preference travels in the embedded config. |

- Older autosaves and standalone project JSON files may require re-importing the original model and companion files for source publishing.
- Named User projects are local to a browser origin. They are not server-side files, and clearing site storage removes them. The JSON download embeds the serialized scene but does not retain original import files; the named browser copy and Editable HTML do. Portable editor files retain their original bundled example catalog and resources; hosted catalog updates require the hosted editor.
- Dependency discovery covers static imports and supported literal asset paths. Custom runtime code can require additional packaging support. A portable editor re-save retains the libraries bundled in the original HTML. Build with the hosted editor when adding new module dependencies or producing ZIP or Playable exports.
- Source publishing reconstructs the scene from its supported material, geometry, and lighting features. Use the serialized player for attached object behavior.
- Render Image's **Realistic** mode uses the experimental WebGPU path tracer in megakernel mode and requires WebGPU. A simple r187 scene and its default environment were rendered in Chrome; broader material, lighting, and device coverage remains unverified. The separate viewport Realistic mode still uses the older WebGL tracer and has not received the same compatibility work.
- When upgrading three.js, compare the editor and vendored build/addons against upstream and rerun the publish and import smoke tests.

## Asset browser integration

The Assets sidebar replaces the old modal chooser. `Sidebar.Assets.js` owns Project/My assets/Mediatheque browsing; `assets/AssetController.js` resolves links into project source files, applies textures through `SetMaterialMapCommand`, and routes viewport drops. `assets/AssetLibrary.js` owns the independent `threeditor-assets` IndexedDB library. `assets/Mediatheque.js` adapts the AMS catalog/search/facet implementation from `languel/artistmodelstudio`; AMS was read from `/tmp/threeditor-ams-reference` because `~/dev/artistmodelstudio` was absent. The full catalog includes models, model animations, originals and BVH links. Default host is `https://languel.github.io/mediatheque/`, verified with `Access-Control-Allow-Origin: *`; the Catalog connection UI overrides it via `threeditor_mediatheque_base`.

`Loader.importGLTFAsset` shares the editor's Draco/KTX2/Meshopt configuration and adds the model as an undoable object without the scene-replacement dialog. Both GLB and glTF external resources are discovered before placement; uploads retain all companions in their batch, including `.bin` files. `assets/AssetTexture.js` is shared by native texture slots and browser material assignment. Viewport drops raycast against scene meshes, then the ground plane. Images can also be assigned to existing material slots. Dragging over Scene/Material tabs exposes native texture slots. No original bytes are discarded: using a remote asset retains a project copy; named User saves and portable snapshots preserve source metadata. A local library copy retains companion paths as a batch. All catalog kinds are browsable. The follow-up below adds type-specific scene importers and previews.

## Asset previews and editable behaviors

The scrollable asset grid uses content-sized rows so populated catalogs cannot collapse thumbnails or labels. `assets/AssetPreview.js` renders catalog images, native video/audio previews, orbitable glTF and math objects, and point previews for SPZ. Local model, math, video and splat thumbnails are generated on a queue. Previewing does not add files or objects to the project.

`AssetController` places images and videos on aspect-correct planes, imports the mathematical payload of SDF/parametric JSON, and removes embedded viewer cameras and lights from glTF. `ModelBehavior.js`, `MathObjects.js`, and `MediaObjects.js` generate ordinary editable object scripts. The marked behaviors run in the editor through `AssetRuntime` and use the normal script lifecycle in Play. The stock glTF mixer exposes per-clip weights, global speed, normalized seek, play, loop, wireframe and per-target morph weights. Audio and video expose transport in Script parameters. Parameter changes and favorites are undoable. SDF definitions become bounded WebGL shaders with depth output; parametric definitions generate native geometry. SPZ imports are point clouds, and audio uses browser playback.

Video canvases keep their upload dimensions stable and preserve a poster frame for serialization. The original video file is packaged and resolved at playback; previews and editor runtime release their temporary URLs. Source exports preserve original glTF clips, the attached behavior, and attribution. User saves and portable HTML preserve the source files and editable parameters.

Validation: `node --test test/*.test.mjs` passes 20 checks. `test/asset-browser.browser.html` verifies wrapper removal, native shader compilation, actual video pixels after texture upload, attached script lifecycle, atomic placement undo, dependency retention and snapshots. Browser QA imported Fox, Gyroid and a Muybridge animation, verified a saved Walk/Run blend, and reopened source ZIP, playable HTML and editable HTML with working controls and video frames. ## Script controls and object activation

- `ScriptParams.js` recognizes `@param`, `@label`, `@slider` and inline ranges such as `const speed = 3; /* 0..3 */`. Numeric ranges constrain sliders and dragging. Finite values typed into the number field can exceed those ranges. `paramValues` and `favoriteParams` travel with each script.
- `ScriptParameterControl.js` shares controls between the Script panel and `Viewport.Parameters.js`. Play moves the same menu into the player, and **Shift+P** also opens it in presentation with the star hidden. `APP.Player.setScriptParameters()` updates the running `params` object and calls an optional `setParameters(next)` hook. Inline constants are substituted when a script starts. The favorites menu belongs to the editor and its presentation mode.
- `ModelBehavior.js` and `MediaObjects.js` generate editable controllers with live parameter hooks. On project load, matching stock model scripts migrate A/B settings to clip weights, and matching stock media scripts migrate to the transport parameters. `MathObjects.js` upgrades original generated math scripts, exposes Enneper domain bounds and Gyroid scale and thickness, and supplies types for evaluator parameters and disposal.
- The outliner power button stores `userData.threeditor.disabled` independently of the eye setting. Disabled branches are excluded from rendering and attached behaviors, and re-enabling a branch uses the saved eye settings. The editor’s director camera remains available when a scene camera is disabled.
- Current verification includes 23 Node tests, the bundled editor diagnostics on all six Mediathèque math payloads, and a Chrome presentation smoke test for **Shift+P** and live parameter changes. The presentation test used a renderer stub. Media migration and live pause, mute and seek were checked with a simulated media element.


## Streams prototype

The `v0.1.2` tag marks the previous params release. The stream work uses a single `StreamRouter` per editor, shared with Play. Routes are undoable edits to `scene.userData.streamRoutes`. The router keeps the latest sample per topic, offers event subscriptions, and evaluates derived topics before scene and hardware destinations. Derived topics have one mapping stage to prevent cycles. Scalar routes resolve explicit target properties and skip disabled objects. Preview provenance blocks physical output even through a mapped topic.

`Sidebar.Streams.js` hosts separate serial, MIDI, and MediaPipe sections with explicit connection controls. `DeviceStreams.js` adapts p5comp line framing and numeric signals. `MediaStreams.js` handles media input, audio RMS, and lazily loaded Tasks Vision models. No device permissions are requested on project load. MIDI and serial outputs must be armed per project. `PoseDriver.js` resolves VRM humanoid indices and drives limb orientations. Pose recording bakes quaternions to a standard editable AnimationClip.

After deploying, smoke-test **File → Examples → streams → Arduino A0** on the hosted editor. Confirm the preview moves in the viewport and in Play before testing devices. Run `node tools/build-stream-examples.mjs` to regenerate the eight stream examples. See [the example guide](editor/examples/streams/README.md) for device setup, expected behavior, and scope. Run `node --test test/*.test.mjs` for the router, device formats, pose driver, and catalog round-trips. Chrome ran all eight previews, drove the Arduino route with injected serial input, packaged a Playable HTML, resolved bones in a minimal binary VRM, and initialized Pose, Hand and Face on synthetic video. Physical MIDI and serial devices, webcam performance, and retargeting across production VRM assets still need testing.


## Main camera, asset editing, and live input

The viewport camera and main camera are separate. **Object → Set as main camera** saves the camera UUID in scene metadata and marks it with a star in the outliner. Play and publishing use that assignment. Older projects use their saved viewport camera when first opened. Attached Fly supports drag to look and the director’s movement keys. Orbit uses world up to keep the horizon level. Controller scripts are edited from the Script tab.

Texture slots apply a clicked asset directly. **Apply to selection…** and drops onto viewport objects or outliner rows use `TextureMapPicker.js` to offer supported material maps. Double-click applies the color map to a selected material or adds a plane. Movie and webcam maps use editable media scripts. Shift-click or F2 opens inline rename for asset labels and folders. Project aliases are undoable scene metadata that preserve file paths and glTF companion references.

Assets is the entry point for uploaded files and reusable webcam and microphone records. **Streams → Assign asset…** accepts images, movies, audio, and live devices. Pausing a live source releases capture and keeps the assignment. Video elements stay mounted while users switch panels or sources. Webcam planes update in the editor and keep the last frame on pause. MediaPipe can use a still image or a live source, and its preview overlays pose, hands, face, and iris landmarks. The source menu, global tracker switch, and per-input topic names are described in the [Streams guide](editor/examples/streams/README.md).

Verification covered 30 Node tests and Chrome checks for camera controls, map assignment, renaming and undo, simulated webcam and microphone assignment, live editor texture updates, paused frames, and still-image input. Physical capture hardware remains to be tested.
